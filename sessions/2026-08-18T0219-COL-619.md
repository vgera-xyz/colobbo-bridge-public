## Summary

Full notification audit across api_node (`apps/api-node` producers + `apps/notification-service`) and web-angular (socket client, bell, settings UI), run end-to-end in one session: discovery → audit → EDA advisory → operator checkpoint → Phase-4 fixes → two PRs. The operator reframed the "duplicate notifications" complaint mid-session into (a) **cross-channel redundancy** (email + socket for one event, no orchestration, in-app structurally ungateable) and (b) **reminder fan-out** (cron emails once per WO row — 10 due = 10 simultaneous emails); both confirmed in code, with the h1–h6 same-channel mechanisms as secondary defects (h4 + h5 confirmed; h1/h3/h6 ruled out — h1's real-world twin is a *loss* bug: socket re-creation silently killed realtime, almost certainly the story behind web PR #712).

**Deliverables:** `wiki/architecture/notification-audit.md` (canonical findings; file:line for every claim) · **ADR-039** (first product-architecture ADR: EDA transport = **SNS→SQS**, BullMQ stays for compute; digest + channel orchestration + per-user prefs live in the future consumer; in-app gating operator-deferred to EDA) · [COL-619](https://linear.app/colobbo/issue/COL-619) anchor ticket (the ONE Linear ticket; relatedTo COL-533/391/441/447/472) · private artifact (checkpoint report, updated post-ship) · operator runbook (7 read-only prod commands settling E1/E2/E3/E6/E8/E9 — operator runs, outputs pending) · pointer comments on COL-391 + COL-472 (coordination only).

**Fixes shipped (operator-approved queue; every fix EDA-surviving, tests with each):**
- **[api_node PR #506](https://github.com/Colobbo/api_node/pull/506)** → `development`, reviewer dagaroth00 — A1 dispatch dedupe (controller collapsed to one send per resolved room key; email paired by original index), A2 export notify-once guard (Redis SET NX, success-path twin of the incident-scarred failure guard), A4 cron hygiene (dead 23:00 job unscheduled; `CRON_TZ` opt-in; `START_CRON_JOBS` kill-switch; Redis overlap lock shared with the manual route), A5 per-row isolation + honest FAILED logging, DG reminder digest (one email per recipient per category per run; single-item groups keep template rendering; `company` role preserves the notifyToEmail always-list for recipient-less rows; `templateEmail` gained optional `htmlBody`).
- **[web-angular PR #781](https://github.com/Colobbo/web-angular/pull/781)** → `development-stage`, reviewer dagaroth00 — W1 listener lifecycle (per-event subjects re-attached on every connect; fixes silent realtime death AND the export service's dead-on-arrival listeners), W3 teardown-always-disconnects + no token-refresh bounce, W2 toast-only-when-new + reconnect resync, W4 settings dialog type alignment + strict null-safety in both settings components.

**Standing rule encoded (operator decision 4/5):** notification-domain PRs in BOTH repos → **dagaroth00**, superseding per-repo defaults — recorded in `wiki/team/ownership.md` §PR-reviewer map (+ stale "Notifications unassigned" line fixed), `glaze.reviewers.domainOverrides.notifications`, and user-global memory (`project-notifications-domain-reviewer.md`).
