## Summary

Stood up **`cs_agent_ro`**, a least-privilege read-only database account on the dev/staging RDS pair, and proved it end-to-end from the operator's laptop. The task as briefed named `colobbo-pgsql` + `colobbodb` as "the dev databases" — **both premises were wrong** and the session's main value was catching that before touching anything: those two instances are STOPPED, and the dev box's own config annotates one `#production database`. Ground truth came from reading the live config on `i-07fa23f00ac52f469` rather than trusting names.

**The estate, as actually mapped:** `colobbo-db-staging-*` hosts **both dev and staging** (dev = `colobbo_db_dev` / `IPMDB_PD`; staging = `colobbo_prod` / `IPMDB_PRD`). Real production is a **separate** RDS pair (`colobbo-db-mssql`, `colobbo-db-postgresql`) in the prod VPC `vpc-0cb71ff5995c1cab8`. Operator confirmed the `*_prod`-named databases on the staging instance are staging data restored from a production snapshot that kept the source name — a rename is with Harish.

**Delivered:** `cs_agent_ro` on PostgreSQL (4 databases) + MSSQL (2 databases), SELECT-only · both credentials in Secrets Manager (`colobbo/dev/cs_agent_ro/postgresql`, `colobbo/dev/cs_agent_ro/mssql`) · local plaintext copy deleted after verified retrieval · `CREATE` revoked from `PUBLIC` on `colobbo_db_dev` · SSM tunnel proven from the laptop for both engines · `glaze.devEnvironment` now carries the full connection map · new global skill **`/dev-db`** (deployed) · [COL-652](https://linear.app/colobbo/issue/COL-652) filed with the findings.

## Verification

- **Read-only proven by attempted writes, not by reading settings.** PostgreSQL: `INSERT` → `42501 permission denied for table Pit_centroid`; `CREATE TABLE` → `permission denied for schema public`. MSSQL: `INSERT` → `Msg 229`; `CREATE TABLE` → `Msg 262`. Every write attempt was wrapped in a rolled-back transaction so nothing could change even had it succeeded.
- **Coverage:** `colobbo_db_dev` 168/168 relations, `colobbo_db_dev_notifications` 8/8, `colobbo_prod` 126/126, `colobbo_prod_notifications` 8/8; MSSQL `IPMDB_PD` 413 tables, `IPMDB_PRD` 410. **Zero** INSERT/UPDATE/DELETE anywhere.
- **Containment:** `IPMDB_Finance`, `IMPDB_PRD_BACKUP`, `ContraPayDB` all refuse the login (`Cannot open database`); cross-database reads blocked (`server principal … is not able to access`). In PostgreSQL the role can `CONNECT` to other databases (a PUBLIC default) but the only readable objects there are PostGIS reference catalogues (`spatial_ref_sys`, `geometry_columns`, …) — **zero business tables**.
- **`CREATE` revoke was safe:** schema ACL `=UC` → `=U`. Owner `sa_pgsql` retains CREATE, so migrations still work — proven by running a full `CREATE TABLE` / `INSERT` / `CREATE INDEX` / `ALTER TABLE` sequence as `sa_pgsql` in a rolled-back transaction. Dev apps healthy after (`401` on :3000, `404` on :7000).
- **Tunnel proven from the laptop**, both engines, with real queries returning real rows. All four SSM sessions terminated afterwards; ports released.
- Gates 1, 13, 14, 19 green at close.

## Corrections made mid-session

Three premises were wrong and were corrected on evidence rather than carried forward:

1. **The briefed dev endpoints were not dev** — caught before any connection.
2. **My own IAM policy draft was wrong.** v1 granted `ssm:StartSession` on `[instance, document]`, which IAM evaluates as **OR** — so it would have allowed a full interactive shell, not just a tunnel. Fixed with a `ssm:SessionDocumentAccessCheck` condition, plus scoping `TerminateSession` to own sessions and narrowing secrets from `colobbo/*` to `colobbo/dev/cs_agent_ro/*`.
3. **"Stale labels from another product" was wrong** — `backend`/`frontend`/`infra` are workspace labels genuinely shared with the **Raku Sight** team. Editing their descriptions would have reached across a boundary the operator wanted kept; the work was dropped.

Also corrected: `wiki/security/` not being in `glaze.wiki.sections` is **not a gap** — `bridge` (127 pages), `strategy`, and `archaeology` are absent too. `sections` is the Memory Lobe's *routing-destination* list, not a directory index.
