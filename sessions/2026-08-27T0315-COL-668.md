## Mobile Message SMS — what was decided

- **Vendor:** Mobile Message. Verified per-message cost 2–4¢ AUD (volume tiers), zero fixed costs; AWS End User Messaging ≈6¢ AUD ($0.04 USD, from their published CSV, found on the sixth attempt); Twilio ≈8¢ AUD ($0.0515 USD). No Twilio SMS exists in any Colobbo repo — the only hits are `// Twilio SendGrid` email comments in the legacy .NET source.
- **Shape (operator):** SMS is a channel on **every** category, like email. Send only when the company's Text toggle is on for the category **and** the recipient has a valid AU mobile **and** it isn't a duplicate; otherwise a quiet skip — no row, no charge, one log line. All policy in notification-service; producers only add `'sms'` to their channel list and supply phones for non-user recipients (booking customer, EOI contact).
- **Sender:** `COLOBBO` once ACMA approves; a Mobile Message virtual number until then (config, not code). Go-live no longer waits on ACMA.
- **Two-way later, built with it in mind:** `custom_ref = companyId:notificationId` + `providerMessageId` on every send; one `resolveSender()`; route-agnostic HMAC middleware; the DLR route is the template for an `/inbound` route. Target case: customer replies Y to confirm a booking. ~3–4 half-days when wanted, nothing undone.
- **Sequence:** PR-A dedupe-at-dispatch (notification-service only, ships first, also closes the email/push duplicate-send gap left by PR #516), then PR-B the channel. 10 half-days total, all in api_node plus a small web-angular toggle flip.

## Review findings folded into the plan before any code

Batched send (one `POST /v1/messages` per dispatch — the existing per-recipient `Promise.all` pattern would 429 past 5 recipients) · re-send only on `failed` (the "skip if sent" rule raced a concurrent `pending`) · `recipientPhone` in the dedupe key (phone-only sends collided on `''`) · provider `Idempotency-Key` · `getTemplateMessage` resolves no SMS body today · no phone anywhere in the pipeline (table, request, client types) · DLR webhook must live under `/api/notifications/*` for the IIS rewrite and mount before `express.json()` · one DLR per message *part* · AU-number normalisation, non-AU = no mobile.
