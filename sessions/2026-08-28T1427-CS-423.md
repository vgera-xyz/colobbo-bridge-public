## Summary

Correlated Lauren Tan's pstack against our substrate, then built the four things the comparison said we were missing. Each was proven before the next started.

The session's most consequential output was not a build. Driving a real api-node instance to prove the harness worked surfaced that **COL-666 / [#581](https://github.com/Colobbo/api_node/pull/581) — the pipeline's one merged PR, our entire proof that the machine works — shipped a route that does not exist at runtime.**

## The finding

`src/routes/healthRoutes.ts` is imported nowhere in `index.ts`. `GET /api/health/ping` returns **401**, not `{ok:true,service:"api-node"}`. Verified against a live instance on three ports.

The codegen did not lie. `src/__tests__/generated/C2.test.ts` says in its own header that the wiring was `brownfield_modify_deferred`, that it mounts the router on a *test-local* Express app, and that it "deliberately do[es] NOT import or assert against the real index.ts". **The skip was recorded honestly and nothing downstream re-read it.** The ticket moved to Dev Done; the PR merged approved.

A second defect follows: the path is absent from `publicRouteAllowlist.ts`, so **even once mounted it would 401 the load balancer it exists to serve**. The pipeline never surfaced that at all.

This sharpens CS-423 Gap 1: the missing capability is not only "run the app", it is **"re-read the skips before calling a ticket done"**. A `skipped[]` entry visible only in a test comment is a skip nobody sees.

## Builds

1. **`verify-api-node`** — [api_node #601](https://github.com/Colobbo/api_node/pull/601) → `development`, jthakkar1981. Skill + `control-api-node` helper (boot/doctor/probe/stop) + four seeded features. Every claim driven against a live instance before being written down. **api-node boots with no database and no real secrets** (lazy Cognito verifier, lazy `pg.Pool`) — five placeholder env vars, ~40s. `.claude/skills/` was gitignored here, so the ignore was narrowed to admit exactly this directory; every other skill stays deploy.sh-owned.
2. **Graph provenance** — `scripts/stamp-graph-provenance.mjs` + weekly `graph-refresh.yml`. Root cause confirmed: graphify stamps `built_at_commit` from the process CWD, and the graphs were built from `graphs/<name>/` inside this repo, so every product graph carried agent-system commit `707c0027`. The stamper **refuses to retro-stamp** — audit mode writes `provenance: UNRECOVERABLE` and leaves `graph.json` untouched, because stamping today's HEAD onto a graph built from an unknown tree would fabricate the currency the script exists to remove.
3. **`maintain-verification-skill`** — global, deployed. Adopting the generator without the maintainer guarantees decay.
4. **`cibo-context`** — per-repo, all four. A product-repo session could see the code but not the 40+ ADRs behind it. Read-only.
