## Summary

Built the ramp's week-2 and week-3 machinery and repaired the defect that motivated it. **The honest number is zero: no ticket has gone through the pipeline since any of these gates landed.** Three weeks of tooling exist; none has run inside a real CI execution. The ramp advances on tickets, not on tooling, so on the record we are still at week 1 with weeks 2–3 built and unproven.

## Shipped

**Skips gate** (`e5e381c6c8`) — week 2. A non-empty `skipped[]` can no longer ride a green run: the PR opens as a **draft**, the tracker is **not** moved to Dev Done, the ticket gets a comment naming each skip, and the job goes red. `allow_skips` is the only escape and records who deferred what and why. Draft rather than a required check because a draft cannot be merged and needs no branch-protection change in three product repos. Absent evidence fails — no audit log exits 4, never a clean report. 15 tests.

**Runtime verify** (`658681f7d2`) — boots the product app from the emitted checkout and judges every endpoint the spec names **by its response body, never its status code**. On api-node an unmounted route and a protected route return byte-identical 401s, so a status assertion would have passed COL-666's dead endpoint. `guarded` and `shape-unspecified` are recorded as UNPROVEN, not passes. Proven against the real thing on two branches: **fail** on `development` (route dead), **pass** on the #616 branch (route mounted). 18 tests.

**Eval harness** (`9520fc8499`) — week 3. One frozen set read two ways: across cases at one substrate version it is a **diagnostic** (crud-validation dropping while greenfield holds says the data-layer knowledge went stale, not the routing); one case across versions is a **benchmark**. Blinding is enforced mechanically — `eval-lint` both checks a case and emits the candidate payload, so what is checked is what is sent. `test` stays legal in prose (a real ticket says "cover it with tests"); it is banned in paths. Machine criteria are read from the run's own artifacts and cannot be passed in. 27 tests. Advisory throughout.

**Case versioning** is the part that keeps the scoreboard honest. A case can be *wrong*: when the world moves, a frozen ticket can fail an agent for **correctly** using the new reality. So cases are editable, every edit bumps `case_version` with a logged reason, every score records `(case_version, substrate_version)`, and `eval-report` compares only within a case version — the break is shown, never smoothed. A drop prints as *a question, not a verdict*.

**COL-685 repaired** ([api_node #616](https://github.com/Colobbo/api_node/pull/616)) — `GET /api/health/ping` now answers `200 {"ok":true,"service":"api-node"}`, verified against a booted instance asserting on the body; full suite 8,920 passed. Mounted ahead of the auth chain rather than added to `publicRouteAllowlist`, because that list's own header forbids genuinely-unauthenticated routes; a pointer comment keeps it findable from there. Flagged for jthakkar1981 to overrule.

Near-term supply is therefore CS-425's first slices plus the new-services work, which is greenfield and the class the pipeline is actually best at.
