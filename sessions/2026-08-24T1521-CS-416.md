## Summary

Execution session for the CS-415 plan tree. Built `Colobbo/github-actions` (new private repo, movable `@v1` tag) as the fleet's single source of CI logic, wired thin caller stubs into all three product repos, and added a **gate-policy layer that protects the gates from being switched off**. Five PRs are open and review-ready; none merged.

The session's method mattered more than any single gate: **every gate was proven by pushing deliberately bad code through it on throwaway PRs**, all closed unmerged. That found eight defects that static review, contract audit and local runs had all missed — most of them cases where a broken gate reported *success*.

The largest finding was incidental. While reviewing a developer's sanitisation approach for a new module, the audit surfaced an **authenticated RCE in api_node**: a string authored in the template designer reaches `new Function()` and executes on the API server. Filed as **COL-642** (Urgent) — https://linear.app/colobbo/issue/COL-642. No pattern-matching rule would have found it — it was found by reading the code.

## Defects found by live-fire (all fixed)

Each of these passed review and local runs, and each reported green while doing nothing:

- **Coverage gate passed a run that measured nothing.** The coverage command was OOM-killed, wrote no report, the fail-closed fallback wrote an empty one — and the gate reported PASS. The absent-file verdict was only read inside the whole-file-floor block, which is skipped at `file-floor: 0` (the day-one posture). `absent-file-policy: fail` was silently inert in the posture every repo starts on.
- **Mutation gate reported 100% on untested code.** Stryker's command runner cannot measure per-test timing, so its timeout collapsed to ~5s, every mutant timed out, and Stryker scores a Timeout as a KILL. Fixed with explicit `timeoutMS` + `timeoutFactor: 1`.
- **One central Node version could not serve one repo.** Mobile's `development` is Angular 16 (`>=20 <21`) while the COL-346 upgrade branch is Angular 22 (`^22.22.3 || ^24.15.0 || >=26.0.0`). Gates now read `engines.node` per branch, so both are green simultaneously and the upgrade needs no CI coordination step.
- **setup-node does not fail on an undeclared runtime** — it warns and falls back to the runner image's Node, which drifts. Engine now asserts the declaration first.
- **Stryker 10 cannot run on Node 20** (Angular 16 pins `<21`), so Mobile's mutation gate could never start. Pinned to 9.x, which spans both sides of the pending upgrade.
- **An unquoted path with a space broke the mutation command** — `geomove copy/` split into two arguments and surfaced as "failed tests in the initial test run", indistinguishable from a broken suite. Mobile has 17 tracked paths with spaces.
- **A green local suite that could never pass on CI** — `./Geomove.page.html` vs the lowercase tracked file. macOS resolved it through five clean local runs; Linux could not.
- **Semgrep rules 87% false-positive on first contact**, and the first fix silently did nothing (semgrep ignores regex lookahead) — caught only by rule fixtures.

## Gate-policy layer (operator ask: "gates cannot be disabled anywhere")

Measured first: **935 `eslint-disable` across the fleet**, 71% of them one rule, zero file-level nuclear disables. A ban was unmergeable; a ratchet was adoptable the same day.

- `gate-policy / suppressions` — blocks NEW `eslint-disable`, `@ts-ignore`, `@ts-nocheck`, `it.skip`, `it.only`, `nosemgrep`, `istanbul ignore`. Existing ones grandfathered.
- `gate-policy / integrity` — blocks `continue-on-error`, `if: false`, paths filters on required checks, repointed engine refs, deleted gate jobs, **redefined gate scripts** (`"lint": "echo ok"`), **deleted test files**, and **new/widened ignore files**. Advisory watch on `publicRouteAllowlist.ts` growth.
- `gate-policy / validation` (api_node, advisory) — reports handlers reading request input without a schema parse. Carries a worked fix in the output; two tests assert the guidance is present.

Proven by tampering: `if: false` on the lint gate makes it report `skipping`, which GitHub counts as **satisfied** — the attack works, and gate-policy caught it. `continue-on-error` turned out to be invalid syntax on a reusable-workflow call, which broke the whole file and took the detector down with it — so gate-policy now lives in its own workflow file and lists itself among the workflows it guards.

## COL-642 — authenticated RCE (Urgent)

`templateController.ts:9` does `const request: Template = req.body` — a TypeScript annotation, erased at runtime, validating nothing. The payload is base64-encoded (opaque to proxy inspection), decoded, stored as a JSON blob. Later `rulesExpression` fields inside it reach `shared/rule-expression.utils.ts:128`:

```
return new Function('return ' + expression)() as boolean;
```

`extractRules` substitutes only recognised conditions; anything unmatched passes through verbatim. The evaluator is fail-open by construction. Operator confirmed users author these in the template designer.

Recommended fix needs no library: after substitution the expression is already a pure boolean combination, so return booleans, evaluate AND/OR directly, and **reject** unrecognised tokens.

Wider audit: **88 files read `req.body`, 7 import Zod** — the layered defence covers ~8% of the request surface.
