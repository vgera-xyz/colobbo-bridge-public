## What the day established (harness)

1. **The product checkout is sealed for the whole chain.** `permissions.deny`
   on `Write/Edit/NotebookEdit(repos/**)` + `chmod -R a-w` proven by a probe
   write. Three emit runs had written into existing files directly, past
   safe-modify and its proofs, each told not to; the third opened a ready PR
   (#686). Two doors after unseal: `apply-safe-modify` (modifies) and new
   `place-greenfield.mjs` (creates, staged under `<run_root>/greenfield/`).
   The runner protocol (`cibo-pipeline` v0.9.0) had to move with it — the first
   sealed run **held before S1 as suspected injection** because the SKILL still
   said "codegen writes into the checkout". Correct behaviour; my inconsistency.
   `run.json` is now initialised before any input is read so a hold at any point
   has a record.
2. **Every seam failure had one shape: a consumer guessing what a producer
   said.** Apply step globbed `*-plan.json`, missed `safe-modify-plan-B1.json`
   (third naming variant), said "nothing to apply", exit 0 → PR #693 opened
   ready with the generated tests and **none of the five source changes**,
   ticket Dev Done. Now reads `modification_plans[].plan_path`; declared-but-
   unresolved is exit 3; `assemble-pr` refuses a partial PR and lists applier
   refusals in the body (accounted = applied + refused-with-reason; the first
   cut counted refused as missing and would have stranded a complete fix).
   Codegen recorded ten files under `emitted_files` vs the contract's
   `files_generated` — `verify-codegen-audit.mjs` fails that at source and
   names the hidden count, and refuses a brownfield modify with no plan behind
   it *independently of the key*. `Assemble PR` ran under `if: always()`, which
   had made the emit-collision gate's own refusal decorative since it was
   written. Regression gate composed paths against one `app_dir`;
   notification-service is a sibling app with its own `node_modules` and flat
   `testing/__tests__/`; installer installed only `apps/api-node`. Validator
   `changes_match_plan` judged against the *planner's* mapping (architect
   legitimately expands it); now architect + test-writer paths, unplanned
   SOURCE → FAILED, unplanned TEST → UNCONFIRMED. A Graphify refresh in the same
   window was reported by the dispatcher as the pipeline run.
3. **Loop-back exists.** Three manual resumes exposed three never-exercised
   paths: `resolve-resume-stage` ignored `escalation.resume_from_stage`; a
   codegen stage's *absent* `lobe_status` read as unready so every halt past
   codegen was unresumable; `github.token` lacked `actions: read` so the resume
   step had never downloaded anything. Architect gained `--prior-findings`
   (0.4.0; backend had it since ADR-021) and **"a finding naming a file is a
   symptom — trace it to the entry point"** after two iterations each closed one
   call frame. `bounded_loop.to` (backward, bounded, triggered; ready-edge graph
   stays acyclic); `ship.chain.json` wires reviewer→architect cap 3; runner
   Step 5a executes it. **Schema-slip retry** (one re-ask with the validator's
   exact line) — two consecutive runs died at the architect on `hints` as string
   and `intent_subtag` as null; the table had given a *semantic* hallucination a
   retry and a *mechanically described* violation none. Policy change the
   operator asked to have raised; made because it cost two runs in an afternoon;
   reversible by deleting one row.
4. **Validator grew up.** `gates_agree` asks whether a blocking gate was
   *honoured* (draft PR), not whether gates differ — it had called the working
   degraded path FAILED. `acceptance_criteria_covered`: an AC counts only when a
   **test** file references it (COL-717 final run: 9 of 10; COL-690 had been
   3 of 7 with nobody noticing). `halt_is_explained`. G2 parse now runs on the
   additive path (insertion-only edits had reached disk unparsed); plain JS
   falls back to `node --check`.
5. **Ledger and dispatch.** Never-started dispatches and operator-superseded
   runs on their own lines, outside the defect denominator (no fifth class —
   the axis stays closed). `outcome_divergence: null` when uncompared.
   `dispatch-run.mjs`: refuses locally what S0 would refuse; `--force`,
   `--pr-title`, `--resume-from`, `--abort-and-replan`; resolves its run by
   workflow + ticket name. Branch collision is a **preflight** via
   `assemble-pr --check-branch-only` (a 30-minute run had collided at the last
   step on a name computable at minute two — with my own leftover draft).
   Gate 30: a tag with no changelog heading fails.
6. **Bridge.** Linear webhook dispatched with no `intent` — every Linear-
   triggered run would have died at S0. Now from an `intent:<x>` or bare label;
   refuses (does not dispatch) without one. Intent literal in three bridge files
   pinned to `glaze.sub_agents.downstream`.

## Product facts established

- **Unassigning a technician revokes their access to the work order.** Removal
  notifications may *name* it (their copy already does, every channel) but must
  never link to it. Templates 33/34 render no link today only because the
  upstream payload lacks a company subdomain — `recordLink()` picks up any
  absolute `docUrl`; template 5 already links that way. Accident, not decision.
  Now guarded by `isRemovalTemplate()` derived from the registry.
- `reassignment.e2e.test.ts:90` asserted the removal email **contains** the View
  button with a `docUrl` fixture — the risk, as a passing test.
- Per-company toggle for categories 37/38 already existed; COL-717 gates
  `notifyToEmail` behind it. In-app gating on a running app: **not exercised**
  (no runtime surface) — on COL-723 for Vaishnavi.
- Dedupe **drops** the later row; it does not merge. "One message listing all
  three" is a digest layer — COL-718 — that sits *above* per-work-order keying
  and depends on #682 merging; reverting #682 would make COL-718 impossible.
