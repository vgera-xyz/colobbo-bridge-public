## The headline

Colobbo's social marketing had posted nothing since 26 April. By the end of this session it is running daily and unattended from a Linear issue, with Vipin's Slack Approve click as the only gate. Three tickets shipped and closed: [CS-438](https://linear.app/colobbo/issue/CS-438) (diagnosis + restore), [CS-439](https://linear.app/colobbo/issue/CS-439) (approval gaps), [CS-440](https://linear.app/colobbo/issue/CS-440) (content source). All on `main`, all deployed to Railway, boot log verified after each.

## CS-438 — why it stopped, and the restore

Two causes stacked. The only content source was `campaigns/sydney-build-2026.json`, whose last post was dated 1 May; the social-radar cron queues only posts dated today, so it had nothing to queue for four months. Then both LinkedIn tokens expired on 17 June (verified with LinkedIn's userinfo endpoint: `EXPIRED_ACCESS_TOKEN`). There is no OAuth refresh path — it was deleted in April because LinkedIn only issues refresh tokens to partner apps. The daily "LinkedIn posts processed: 12" line was the outreach cron looping the 12 past-dated Sydney posts and skipping each as image-type; no backlog existed.

Other verified answers: the approval gate for image posts always existed and always landed in #colobbo-radar (no `SLACK_CHANNEL` set, hardcoded default); `/api/content-calendar/approve` never existed; Instagram + Facebook code works and the Meta Page token is valid with no expiry (its `data_access_expires_at` passed 21 July but publishing still works — proven); HubSpot has no blog configured; TikTok and G2 have nothing.

Restore, by Vipin's hand with CC verifying: both LinkedIn tokens rotated (expiry 2026-11-08), `META_TOKEN_EXPIRES_AT` set to 2099-12-31, Sarah's member id corrected to `Mgp9w-NXWB` (LinkedIn's `sub` — the old value differed in letter case). A one-post smoke campaign published to LinkedIn, Facebook and Instagram from one Approve click (20:58 AEST). Lesson: the image badge renders `event_name` falling back to the campaign `name`, so an internal campaign name is public copy — caught before approval, fixed via PR #80.

Commits: `2bf844d00e`, `47bf1f3e7f`, `6da4d186a9`. PRs #78, #80, #81.

## CS-439 — the three approval gaps

1. **Persistence.** Railway has no volume, so `data/` would not survive a restart. Every job now mirrors to S3 (`social-jobs/<id>.json`, same bucket as the preview images) on every transition; `hydrate()` reloads at boot before the cron starts. Approve re-fetches the PNG from S3. A job caught mid-publish reloads as `failed: publish_interrupted_by_restart` and is **not** retried (channels unknown → blind retry double-posts); card + thread tell the operator to check.
2. **Text posts.** Now a caption-only Slack preview, LinkedIn only on approve. The outreach cron no longer publishes LinkedIn at all. Manual `/linkedin/post` + `/linkedin/schedule` require `confirm: true`.
3. **`SLACK_CHANNEL` required.** Fallback removed; unset = nothing posts, job fails loudly. Set to `C0AN3TMDLJJ` in Railway before the merge.

Plus: the Cibo bridge Worker ignores plain channel messages (it had been replying to every social-radar summary). Deployed via `wrangler deploy` by Vipin.

Commits: `356c61ddbd`, `7a8513a1c2`. PR #82.

## CS-440 — the Linear Content Calendar as a campaign

`lib/content-calendar/` reads the month's "Content Calendar — <Month> <Year>" issue at the top of every social-radar run and registers a **virtual campaign** (`content-calendar-YYYY-MM`) with the loader in exactly the JSON-file shape. The existing preview → Approve → fan-out runs unchanged. Brand card → image post with the issue's headline/subtext verbatim, badge "Connected Field Platform" (Vipin's call, no leading "The"); "Media: None" → text post. Optional per-post `**CTA:**` and `**Author:**` lines. Edits to a Brief count until 10:00 AEST on the day.

Drafting: brand rules (verbatim from the brief) sit above four playbooks vendored from coreyhaines31/marketingskills (MIT) under `screenshot-service/prompts/skills/`, trimmed to what applies to a 150–250 word LinkedIn post: social + copywriting always; marketing-psychology for founder_story / thought_leadership; competitors when the topic or brief names a competitor or a renewal. A deterministic check (FSM, "GIS tasking", AI/Claude/Cibo, prices, capitalised brand) triggers one regenerate naming the violation; a still-dirty draft reaches Slack flagged "Needs edit", never dropped.

Linear writes: comment per event (draft sent with Slack link / published with URLs) + checkbox tick as a scoped read-modify-write of one post block, re-read first, skipped if the block changed. Dedupe = persisted job first, tick second. Failure modes: no issue → one alert per month (S3 marker); Linear down → alert, JSON campaigns unaffected; already ticked → skipped.

Engine additions (all additive): `loader.registerVirtual`, per-post `cta_text`/`cta_url` + `channels` overrides, `systemAddendum` on both drafting calls, `lib/campaigns/hooks.js` (queued/published).

**Found by the dry run:** `services/claude.js` pins `claude-sonnet-5`, which thinks adaptively; the thinking counts against `max_tokens`, so the 1500-token drafting calls returned a lone `thinking` block and no text. `withSampling()` now floors `max_tokens` at 8192 for models that reject `temperature` (the Claude 5 tell).

Dry run for 15 Sep (CS-443 Post 1): 8 posts parsed, schema valid, 194-word draft, brand check clean. Pasted on CS-440. Decision (Vipin): the brand rule stays strict — the category name is never printed, even quoted for rejection.

Commit: `e7e2f6da74`. PR #83. Deployed: Railway `24eaead8`; boot log `calendar content-calendar-2026-09 registered from CS-443: posts=8 skipped=0 invalid=0`; live `/api/campaigns` lists it active.
